## 修正漏收的具体原因

HelloGitHub、逛逛GitHub及部分创作者的标题只有期号、开源周报或作品名，摘要缺失或不介绍主题，但公开订阅已附完整文章。原先必需关键词只检查标题/摘要，漏掉正文中的创作模型、视频工具和项目链接。

新增显式配置 `ingestNoiseFilter.includeBodyForTopic: true`：仅当来源启用且订阅已提供 `bodyStatus: "ok"` 的正文时，把该正文加入必需关键词检查。没有额外正文抓取；其他来源保持原行为，排除词、豁免词和类别规则也保持原行为。正文不能用“research”绕过标题广告排除。回归同时验证了未启用、pending 正文、无关数据库正文、大小写、词边界及错误配置。

已调整的既有来源：歸藏的AI工具箱 · 公众号公开订阅、AI寒武纪 · 公众号公开订阅、山行AI · 公众号公开订阅、袋鼠帝AI客栈 · 公众号公开订阅、沃垠AI · 公众号公开订阅、卡尔的AI沃茨 · 公众号公开订阅、What’s New in Generative Media。仅更新这几个来源的主题过滤配置，保留原有 ID、启停状态、采集进度与其它配置；未重置游标或重新伪造历史日期。其较旧的漏收素材仍受原有发现窗口限制，本批不承诺全部历史教程已补齐。新版本与新文章继续走原有预筛、质量判断、归组和精选门槛。

最终正文匹配范围收窄到 ComfyUI、Stable Diffusion、AI 视频/生图/配音、分镜、生成模型、创作工具等明确主题；没有把“workflow”“图片”“视频”单独作为混合 RSS 的正文通行条件。普通 Agent、教育与科技消息仍可能在第一层提到创作词，但需经过领域预筛，不等于公开展示或入选。

## 时间、归属和平台边界

- GitHub 项目使用公开 release API 的 `published_at`，保留预发布版本标识，过滤草稿；不使用仓库更新、提交时间或 release 修改时间充当新发布。LocalMiniDrama 的 Atom 看似有 1 条近期更新，但 release API 确认近 30 天首次发布为 0，未导入本批。这一对照保存在候选证据中。
- 新建仓库监测与本批真实版本发布是不同入口；本批新增的 7 个项目发布源均有近期首次发布，未将前一批没有新项目的五个监测源重复计数。
- 公众号取公开 RSS 桥接，可能延迟或缺漏；归属使用真实作者/机构，桥接服务不充当内容发布者。优设作者专栏按真实主页核对，HTML 相对日期无法可靠解析时，读取文章 `og:article:published_time` 并按 +08:00 解释；未知日期排除，不用抓取时间代替。
- 公开社区来源保留原发帖时间，评论、问答、工作流及项目分享都可能进入候选；只有提供足够相关材料且满足既有筛选的内容才能展示。不下载视频，不伪造字幕。
- 另核验 18 位 YouTube 创作者频道，取得大部分真实频道 ID，但其原生订阅未通过。上传播放列表订阅复查也失败。B站公共 RSS 桥接超时/403；Reddit 其余社区返回 429，只有 StableDiffusion 成功。没有把这些失败地址导入或计入可用数，也没有绕过登录、验证或网络地址检查。
- 优优教程网已显示迁移至 AI星踪岛，原 feed 不可用。新站工具列表、本期无近期条目的其他创作者、无 release 的 ComfyUI 插件均保留为候选核验，不虚报完成接入。你丫才美工的全部投稿页出现重复超时，改用同作者“设计文章”公开入口，重新解析到 25 条文章和 1 条近期匹配，实际采集恢复 ok。最终 30 个新来源及 7 个调整来源均健康为 ok；修复前后配置与日期证据保存在 checks 的 profileRepair 字段。
